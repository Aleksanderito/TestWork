
1. Получить всех кандидатов с кастомным признаком `super_boss = true`.
2. Для каждого кандидата добавить к названию должности суффикс ` — Супер Босс`.
3. Не добавлять суффикс повторно при следующих запусках.
4. Сохранить изменение через интеграционный слой.
5. Записать аудит действий в JSON Lines.




`SuperBossProcessor` содержит только бизнес-логику и не зависит от конкретного API WebTutor.

`CandidateRepository` задаёт контракт:

- `get_super_boss_candidates()`
- `update_position(candidate_id, position_name)`

Поэтому транспорт можно заменить без изменения бизнес-логики: REST, SOAP либо другой подтверждённый интерфейс целевой установки WebTutor.


## Запуск

Из корня проекта:

```bash
python main.py
```

По умолчанию используется `FakeCandidateRepository`.

Пример результата:

```text
found=4 updated=2 skipped=2 failed=0

Candidates after processing:
1: 'Менеджер по продажам — Супер Босс'; super_boss=True
2: 'Разработчик'; super_boss=False
3: 'Директор — Супер Босс'; super_boss=True
4: 'Аналитик — Супер Босс'; super_boss=True
5: ''; super_boss=True
```


По умолчанию журнал хранится здесь:

```text
logs/audit.jsonl
```

JSONL выбран вместо одного большого JSON-массива, потому что события можно безопасно дописывать по одной строке.

Пример успешного изменения:

```json
{"timestamp":"2026-08-18T11:00:00+03:00","event":"candidate_updated","run_id":"...","user":"test-user","candidate_id":1,"old_value":"Менеджер","new_value":"Менеджер — Супер Босс","status":"success"}
```

Каждый запуск имеет уникальный `run_id`. События:

- `job_started`
- `candidate_updated`
- `candidate_skipped`
- `candidate_update_planned`
- `candidate_update_failed`
- `job_finished`

Таким образом можно восстановить историю конкретного запуска.

## Идемпотентность

Перед изменением программа проверяет:

```python
position.endswith(" — Супер Босс")
```

Поэтому повторный запуск не создаёт строку:

```text
Менеджер — Супер Босс — Супер Босс
```

## Обработка ошибок

Ошибка обновления одного кандидата:

- записывается в технический лог;
- записывается в audit log;
- увеличивает `failed`;
- не останавливает обработку следующих кандидатов.

Это важно для пакетной обработки.
